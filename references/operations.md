# Команды и формат плана

Помощник `scripts/project_cleanup.py` расположен относительно каталога скилла. Подставь абсолютные пути. Windows: `python` или `py -3`; macOS/Linux: `python3`. Нужен Python 3.10+ без сторонних пакетов.

## Инвентарь

```text
python "<skill>/scripts/project_cleanup.py" inventory --root "<project>" --out "<project>/.artifact-cleanup/inventory.json"
```

Скан читает метаданные, не содержимое всех файлов. JSON: `files`, `skipped`, `errors`, Git-состояние. Документы/медиа включены по умолчанию; нестандартный тип: `--include-ext .drawio --include-ext .mydoc`. Передавай те же расширения в prepare. Исходники не включаются в список документов. Защитные файлы включаются независимо от расширения. Отсутствие в инвентаре не доказывает отсутствие файла.

Пропускаются VCS, конфигурационные каталоги агентов/IDE, зависимости, некоторые build/cache-каталоги, `.artifact-cleanup`, вложенные репозитории, ссылки/junctions и специальные файлы. Внутренности защищённых каталогов не сканируются. Все пропуски и ошибки перечисляются. Git-игнорируемые файлы вне пропущенных каталогов видны. Вложенные репозитории проверяй отдельно по явному охвату.

## Подготовка

Агент создаёт `selection.json`:

```json
{
  "items": [
    {
      "path": "plans/export-plan.md",
      "reason": "Все пункты реализованы; уникальных решений в плане нет.",
      "evidence": ["src/export.py:40 — экспорт реализован", "tests/test_export.py:18 — проверка формата"],
      "reference_check": "Проверены пути, импорты инструкций и ссылки; использований не обнаружено; динамических ссылок нет.",
      "confidence": "high"
    }
  ]
}
```

Пути относительно корня, через `/`, без масок, `..` и каталогов. Доказательства должны быть содержательными; `reference_check` отражает фактическую проверку и её пределы. Скрипт проверяет заполненность, а не истинность доказательств.

```text
python "<skill>/scripts/project_cleanup.py" prepare --root "<project>" --selection "<selection.json>" --out "<project>/.artifact-cleanup/plan.json"
```

Команда создаёт новый план и печатает SHA-256 **всего файла**, количество, объём и точный список. Существующие отчёты не перезаписывает; используй новые имена. План фиксирует размер, время, SHA-256 и Git-состояние кандидатов. Защищённые пути, изменённые tracked-файлы, неподдерживаемые расширения, hard links, выход за корень и повторы отклоняются.

Новые и Git-игнорируемые файлы не считаются автоматически расходными. Для них особенно важен карантин: Git не гарантирует восстановление. Недоступный Git отмечается как `unknown`; раскрой это в отчёте.

## Выполнение — после одобрения

```text
python "<skill>/scripts/project_cleanup.py" apply --plan "<plan.json>" --approve "<SHA-256 показанного плана>"
```

Флаг не получает человеческое согласие: агент обязан получить его в разговоре. Не подставляй автоматически новый хеш вместо одобренного. Изменение плана делает старый хеш непригодным.

Все кандидаты проходят предварительную проверку до начала операции. Перед удалением каждого оригинала повторно проверяются его отпечаток и резервная копия. Не запускай одновременно с редактированием тех же файлов: проверки не заменяют блокировку рабочей папки. Новые зависимости от кандидата проверяет агент.

Карантин: `<project>/.artifact-cleanup/quarantine/<id>/`. Файлы — `000001.blob`; `journal.json` хранит пути, хеши и состояние. Проверенная копия и журнал предшествуют удалению оригинала. При прерывании возможен частичный результат; проверь журнал. Команда не удаляет каталоги и не меняет Git index. Удаление tracked-файла видно в `git diff`.

Карантин сохраняет занимаемый объём и остаётся внутри проекта. Его может видеть Git или широкий поиск. `.gitignore` автоматически не изменяется.

## Восстановление

```text
python "<skill>/scripts/project_cleanup.py" restore --journal "<project>/.artifact-cleanup/quarantine/<id>/journal.json"
```

Проверяются целостность копий и пути. Существующий файл не перезаписывается: совпадающий отмечается как уже присутствующий, различающийся вызывает отказ до восстановления остальных. Копии сохраняются после восстановления. При незавершённой очистке отсутствие копии допустимо, только если оригинал ещё на месте и совпадает.

Если проект переехал, помощник откажется использовать старый корень: сначала согласуй восстановление в новый каталог вручную. Безвозвратного удаления нет.

## Перенос в другой агент

Копируй **весь** каталог `project-cleanup`. Актуальный Codex: `~/.agents/skills/project-cleanup` или проектный `.agents/skills/project-cleanup`. Некоторые установки используют `~/.codex/skills`; избегай двух копий с одинаковым именем в одновременно сканируемых местах. Claude Code: `~/.claude/skills/project-cleanup` или `.claude/skills/project-cleanup`. В другом агенте используй его каталог Agent Skills либо явно попроси прочитать `SKILL.md`.
