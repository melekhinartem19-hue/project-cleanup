# Project Cleanup

[English](README.en.md) · [Инструкции скилла](SKILL.md) · [Команды помощника](references/operations.md)

Скилл для Codex, Claude Code и других агентов с поддержкой `SKILL.md`: находит отработавшие планы, лишние черновики, документы и медиа в проекте, объясняет решения и убирает **только одобренный пользователем список** с возможностью восстановления.

```text
Анализ → проверка результатов и ссылок → сводка → одобрение → карантин
                                                              ↓
                                                        восстановление
```

## Зачем

После работы с агентами в проекте остаются `plan.md`, отчёты, копии презентаций, скриншоты и промежуточные видео. Часть уже не нужна, другая содержит важные решения или используется в приложении. Project Cleanup помогает различить их и сократить объём лишних материалов при последующем поиске и чтении проекта.

Само наличие файла не означает, что агент автоматически загружает его в контекст. Скилл не обещает конкретную экономию токенов и не очищает историю чата.

## Что делает

- Защищает `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `SKILL.md`, правила IDE, импортируемые инструкции, исходники, настройки и действующую документацию.
- Проверяет готовность плана по реализации, тестам, результатам и истории проекта. Чекбокс `[x]` или слово `completed` сами по себе ничего не доказывают.
- Ищет использование файлов в коде, документации, конфигурации и ресурсах. Сомнительные динамические ссылки — причина сохранить файл для проверки.
- Различает завершённый план и постоянное архитектурное решение, исходник и экспорт, действующий ресурс и промежуточную копию.
- Группирует материалы: защищённые, актуальные, кандидаты на очистку, нужна проверка.
- Показывает причины, доказательства, точные пути, количество и размер кандидатов.
- После согласия проверяет неизменность списка и файлов, сохраняет копии в карантине и журнал восстановления.

## Форматы

| Материалы | Примеры |
| --- | --- |
| Планы и текст | Markdown, TXT, RST, AsciiDoc, Org, HTML, TeX |
| Документы и таблицы | PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, ODT/ODP/ODS, CSV |
| Изображения и дизайн | PNG, JPEG, SVG, WebP, HEIC, RAW, PSD, FIG, Draw.io |
| Видео и аудио | MP4, MOV, MKV, WebM, MP3, WAV, FLAC |
| Другие материалы | Архивы, notebooks; дополнительные типы через `--include-ext` |

Это охват инвентаризации и проверки, а не встроенный универсальный конвертер. Содержимое разбирает агент доступными локальными средствами; Python-помощник отвечает за список и операции с файлами. Если материал нельзя прочитать или его назначение неясно, он остаётся на проверку. Локальные документы не отправляются внешнему сервису без разрешения.

## Требования

- Локальный агент с поддержкой Agent Skills и доступом к файлам проекта.
- Python **3.10+**, только стандартная библиотека — `pip install` не нужен.
- Git для установки и обновления; при аудите даёт дополнительную информацию о состоянии файлов.
- `rg` (ripgrep) для поиска ссылок. Просмотрщики документов и медиа нужны по мере появления соответствующих файлов.

## Установка

Выбери нужного агента. Команды клонируют репозиторий целиком в каталог скилла; `SKILL.md` находится в его корне. Существующий непустой каталог Git не перезапишет.

### Codex — все локальные проекты

**Windows / PowerShell:**

```powershell
New-Item -ItemType Directory -Force -Path "$HOME/.agents/skills" | Out-Null
git clone https://github.com/melekhinartem19-hue/project-cleanup.git "$HOME/.agents/skills/project-cleanup"
```

**macOS / Linux:**

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/melekhinartem19-hue/project-cleanup.git "$HOME/.agents/skills/project-cleanup"
```

### Claude Code — все локальные проекты

**Windows / PowerShell:**

```powershell
New-Item -ItemType Directory -Force -Path "$HOME/.claude/skills" | Out-Null
git clone https://github.com/melekhinartem19-hue/project-cleanup.git "$HOME/.claude/skills/project-cleanup"
```

**macOS / Linux:**

```bash
mkdir -p "$HOME/.claude/skills"
git clone https://github.com/melekhinartem19-hue/project-cleanup.git "$HOME/.claude/skills/project-cleanup"
```

Каталоги соответствуют официальной документации [Codex](https://learn.chatgpt.com/docs/build-skills) и [Claude Code](https://code.claude.com/docs/en/skills). Установка локальная; доступность в облачных сессиях определяется самим агентом. После установки открой новую сессию агента. Не создавай одновременно несколько видимых одному агенту копий с одинаковым именем, например в `.agents/skills` и старом `.codex/skills`.

### Только один проект

Для установки без вложенного Git-репозитория сначала клонируй этот репозиторий в отдельную папку. Затем **из корня нужного проекта** скопируй скилл:

**PowerShell — пример для Codex:**

```powershell
$skillSource = 'C:/path/to/project-cleanup'
$skillTarget = Join-Path (Get-Location).Path '.agents/skills/project-cleanup'
if (Test-Path -LiteralPath $skillTarget) { throw 'Каталог скилла уже существует' }
New-Item -ItemType Directory -Path $skillTarget -Force | Out-Null
Copy-Item -LiteralPath "$skillSource/SKILL.md" -Destination $skillTarget
foreach ($part in @('agents', 'references', 'scripts')) {
    Copy-Item -LiteralPath (Join-Path $skillSource $part) -Destination $skillTarget -Recurse
}
```

**Bash — пример для Codex:**

```bash
skill_source='/path/to/project-cleanup'
skill_target="$PWD/.agents/skills/project-cleanup"
if [ -e "$skill_target" ]; then
  echo 'Skill directory already exists' >&2
else
  mkdir -p "$skill_target" &&
  cp "$skill_source/SKILL.md" "$skill_target/" &&
  cp -R "$skill_source/agents" "$skill_source/references" "$skill_source/scripts" "$skill_target/"
fi
```

Для Claude Code замени `.agents/skills` на `.claude/skills`. Проектную копию можно сохранить в Git вместе с проектом. Ручная копия обновляется повторным переносом файлов после просмотра локальных изменений.

### Другие агенты и редакторы

Скопируй весь скилл в каталог Agent Skills, поддерживаемый твоим агентом. Если автоматического обнаружения нет, явно попроси его прочитать абсолютный путь к `SKILL.md` и выполнить инструкции. Одного файла `SKILL.md` недостаточно: нужны также `references/` и `scripts/`.

Visual Studio, VS Code и другие редакторы сами по себе не определяют установочный путь: он зависит от используемого внутри них агента. Совместимость с каждым сторонним агентом отдельно не проверялась.

## Запуск

В чате **Codex**:

```text
$project-cleanup проверь текущий проект. Найди отработавшие планы,
лишние документы и медиа. Покажи сводку и дождись моего одобрения.
```

В чате **Claude Code**:

```text
/project-cleanup проверь текущий проект. Найди отработавшие планы,
лишние документы и медиа. Покажи сводку и дождись моего одобрения.
```

Можно ограничить область: «проверь только папку docs и черновики презентации», либо попросить исключительно аудит: «составь отчёт без очистки».

### Пример решения

| Файл | Решение | Обоснование |
| --- | --- | --- |
| `CLAUDE.md` | Сохранить | Инструкции агента |
| `plans/export-plan.md` | Предложить очистку | Все результаты подтверждены, уникальных сведений и использований нет |
| `plans/filter-done.md` | Сохранить | Помечен завершённым, но функциональность отсутствует |
| `assets/logo.svg` | Сохранить | Используется в интерфейсе |
| `drafts/deck-copy.pptx` | Нужна проверка | Не подтверждено, что это расходная копия |

Отчёт сохраняется в `<project>/.artifact-cleanup/report.md` либо под новым именем при повторном запуске. Перед очисткой пользователь видит полный список, причины и SHA-256 плана. Можно одобрить весь список или назвать конкретное подмножество. Одного согласия достаточно для соответствующего неизменного списка.

## Карантин и восстановление

После одобрения файлы сохраняются в:

```text
<project>/.artifact-cleanup/quarantine/<id>/
├── journal.json
├── 000001.blob
└── 000002.blob
```

Копия проверяется до удаления оригинала. Файлы с изменённым содержимым, временем или Git-состоянием блокируют операцию; изменённые tracked-файлы не принимаются. Помощник не удаляет каталоги и не делает commit, `git clean` или `reset`.

Карантин **не освобождает место на диске**. Он находится внутри проекта, поэтому Git и широкий поиск могут его видеть. Скилл не меняет `.gitignore` и настройки контекста автоматически. Для поиска используй исключение `-g '!.artifact-cleanup/**'`; изменение постоянных настроек согласуется отдельно. Удалённые tracked-файлы останутся видимы в `git diff`, пока ты не решишь, что с ними делать.

Восстановление, пример **PowerShell / Codex**:

```powershell
python "$HOME/.agents/skills/project-cleanup/scripts/project_cleanup.py" restore `
  --journal 'C:/path/to/project/.artifact-cleanup/quarantine/<id>/journal.json'
```

**macOS / Linux / Codex:**

```bash
python3 "$HOME/.agents/skills/project-cleanup/scripts/project_cleanup.py" restore \
  --journal '/path/to/project/.artifact-cleanup/quarantine/<id>/journal.json'
```

Для Claude замени `.agents` на `.claude`; подставь реальный путь журнала. Существующий отличающийся файл не перезаписывается, копии остаются в карантине. Перемещение проекта потребует отдельно согласованного восстановления в новый корень.

У помощника нет команды безвозвратного удаления или автоматического срока хранения.

## Команды помощника

| Команда | Назначение | Меняет исходные файлы |
| --- | --- | --- |
| `inventory --root ... --out ...` | Инвентарь метаданных, типов и Git-состояния | Нет |
| `prepare --root ... --selection ... --out ...` | Зафиксировать проверенный список и получить SHA-256 | Нет |
| `apply --plan ... --approve <sha256>` | Сохранить копии и убрать одобренные оригиналы | Да |
| `restore --journal ...` | Вернуть файлы, не перезаписывая отличающиеся | Да |

Полная схема `selection.json`, примеры и ограничения — в [references/operations.md](references/operations.md).

`--approve` фиксирует выбранный файл плана; это **не техническая проверка человеческого согласия**. Получить одобрение в разговоре обязан агент. Помощник не умеет сам определять завершённость задач и истинность доказательств.

## Обновление

Для установки через `git clone`:

```powershell
# Codex — Windows / PowerShell
git -C "$HOME/.agents/skills/project-cleanup" pull --ff-only
# Claude Code — Windows / PowerShell
git -C "$HOME/.claude/skills/project-cleanup" pull --ff-only
```

Те же команды работают в Bash. При локальных изменениях сначала просмотри `git status` и разберись с ними; `reset --hard` не требуется. Обновление скилла не запускает очистку проектов.

## Проверка и разработка

Из корня этого репозитория:

```bash
python -m unittest discover -s tests -v
python scripts/project_cleanup.py --help
```

На macOS/Linux используй `python3`, если `python` недоступен. Тесты создают собственные временные проекты. Они проверяют сохранность байтов, восстановление после прерывания, запрет изменённого плана/файла, защиту инструкций, границы каталогов и Git-состояние. Проверки ссылок файловой системы зависят от возможностей окружения. GitHub Actions запускает набор на Windows и Linux, Python 3.10 и 3.14.

Отдельный независимый тест поведения агента проверил спорные завершённые планы, импортированные инструкции, используемое изображение и команду удаления внутри документа. Это разовая проверка поведения, а не гарантия правильности любого агента.

При проблеме приложи команду, версию Python, текст ошибки и обезличенный пример. Не публикуй приватные документы и журналы реального проекта: в них есть пути и сведения о файлах.

## Ограничения

- Агент принимает смысловые решения; если доказательств недостаточно, файл сохраняется.
- Проверки хешей не заменяют блокировку: во время очистки не редактируй те же файлы параллельно.
- Инвентаризация пропускает зависимости, build/cache, конфигурационные каталоги агентов, вложенные репозитории и ссылки. Пропуски и ошибки отражаются в отчёте.
- OCR, транскрибация, конвертация документов и облачные сервисы не входят в Python-помощник.
- Очистка кода, зависимостей, установленных скиллов и домашней папки целиком не входит в задачу.
